# 할인도사 테스트 계획

## 목적

Play Store 내부 테스트와 비공개 테스트에서 앱이 쇼핑 정보 앱으로 안정적으로 동작하는지 확인합니다.

## 테스트 환경

- Android Studio Emulator
- 실제 Android 기기 1대 이상
- 네트워크 정상 상태
- 네트워크 불안정 상태
- 세로 화면 기준

## 핵심 시나리오

아래 항목 중 `자동 검증` 표기는 `npm run smoke:local`, `npm run qa`, `npm run release:doctor`에서 커버합니다. `수동 확인` 표기는 실제 Android 기기 또는 에뮬레이터에서 최종 확인합니다.

### 홈

- [x] 자동 검증: 앱 실행 시 홈 화면이 바로 표시된다.
- [x] 자동 검증: 상단 헤더, 업데이트 시간, 새로고침 버튼이 보인다.
- [x] 자동 검증: 실시간 할인 정보와 특가 카드가 보인다.
- [x] 자동 검증: `오늘 바로 볼 할인 지도`에서 검수 완료 구매 링크, 무료배송, 마감임박, 인기 급상승으로 바로 좁혀볼 수 있다.
- [x] 자동 검증: 오늘의 추천, 인기 특가, 마감 임박, 무료배송 특가 섹션이 보인다.
- [ ] 수동 확인: 상품 이미지 비율이 실제 Android WebView에서 깨지지 않는다.

### 검색/필터

- [x] 자동 검증: 판매처명으로 검색된다.
- [x] 자동 검증: 카테고리 탭 선택 시 목록이 바뀐다.
- [x] 자동 검증: 카테고리 화면은 대표 특가와 구매 링크 확인 수를 표시해 카테고리별 탐색 품질을 보여준다.
- [x] 자동 검증: 무료배송만 보기 필터가 작동한다.
- [x] 자동 검증: 핫딜만 보기 필터가 작동한다.
- [x] 자동 검증: 마감임박만 보기 필터가 작동한다.
- [x] 자동 검증: 최신순, 할인율 높은 순, 가격 낮은 순, 마감 임박 순 정렬이 작동한다.
- [x] 자동 검증: 검색 결과 없음 UI가 표시된다.

- [x] 자동 검증: 상세 페이지에 이미지, 상품명, 판매처, 가격, 배송, 설명, 추천 이유, 유의사항이 보인다.

- [x] 자동 검증: 구매 이동 확인 모달은 이동 예정 판매처 도메인과 링크 상태를 표시한다.

- [ ] 수동 확인: Android Custom Tab 또는 외부 브라우저가 실제 기기에서 자연스럽게 열린다.
- [ ] 수동 확인: 공유하기 버튼이 기기 공유 시트로 열린다.
- [x] 자동 검증: 찜하기 버튼과 관심 특가 목록이 작동한다.
- [x] 자동 검증: 찜 목록이 비어도 구매 링크 확인 특가 CTA와 추천 저장 후보가 보인다.
- [x] 자동 검증: 관련 특가 추천이 보인다.
- [x] 자동 검증: 상세 페이지에 가격 알림 신청 패널이 보이고 실제 푸시 권한 요청 없이 기기 저장 구조로 안내한다.

- [x] 자동 검증: 하트 버튼으로 찜 저장이 된다.

- [x] 자동 검증: 찜 탭에서 목록이 보인다.

- [x] 자동 검증: 상세에서 저장한 가격 알림 조건을 알림 탭에서 확인하고 해제할 수 있는 UI가 보인다.
- [x] 자동 검증: 홈 하단 탭 알림 화면에서도 저장한 가격 알림 목록이 보이고, 회원 탈퇴/기기 데이터 삭제 범위에 가격 알림 조건이 포함된다.

### 마이/정책

- [x] 자동 검증: 커뮤니티/placeholder 링크는 직접 구매 링크로 노출하지 않는다.

- [x] 자동 검증: 운영 피드 import dry-run은 placeholder 또는 커뮤니티 게시글 링크를 거부한다.
- [x] 자동 검증: `/api/metrics`는 링크 품질 요약과 링크 검수 큐를 제공한다.
- [x] 자동 검증: 관리자 화면에는 링크 검수 큐와 판매처 확인 액션이 표시된다.
- [x] 자동 검증: `/commercialization` 출시 준비 보드는 구매 링크 확인율, 남은 링크 검수, Supabase OAuth Provider 외부 설정, 실제 운영 전환 순서를 표시한다.
- [x] 자동 검증: `/commercialization` 출시 준비 보드는 출시 준비 단계와 다음 우선 조치 큐를 표시한다.

- [x] 자동 검증: sitemap에는 서비스 안내, 개인정보처리방침, 상업화 준비 페이지가 포함된다.

## 자동 검증

```bash
npm install
npm run lint
npm run build
npm run build:android
npm run cap:sync
npm run smoke:local
npm run qa
npm run audit:commercial
npm run perf:budget
npm run release:evidence
npm run qa:release
npm run release:doctor
```

개발 서버가 켜진 상태에서는 아래도 실행합니다.

```bash
npm run smoke
```

`smoke:local`은 개발 서버 실행, 헬스체크 대기, smoke 검증, 서버 종료까지 한 번에 수행합니다.
현재 smoke는 36개 항목으로 홈/검색/링크/관리자/상업화 준비/정책뿐 아니라 OAuth callback, 온보딩, 회원 탈퇴 guard까지 확인합니다.
`qa`는 lint, 로컬 smoke, Next.js build, release doctor를 포함합니다.
`audit:commercial`은 high/critical npm 취약점이 남아 있으면 실패합니다.
`perf:budget`은 정적 export, JS/CSS, APK/AAB, 스토어 이미지가 출시 예산을 넘으면 실패합니다.
`release:evidence`는 커밋, 앱 버전, APK/AAB, 스토어 이미지, 남은 수동 확인을 `docs/release-evidence.md`에 기록합니다.
`release:doctor`는 Android/iOS 패키징, OAuth/딥링크, Supabase 회원 데이터 동기화, 상업화 준비 화면, 상품 상세 링크 35개 이상 및 65% 이상 보강률, 내부 점수 비노출, 출시 당일 체크리스트, 스크린샷 스토리보드, 보관/위탁/삭제 정책 문구, 스토어 산출물까지 확인합니다.
`qa:release`는 `qa`, `audit:commercial`, Android 정적 빌드, Android/iOS Capacitor sync, `perf:budget`, release doctor를 한 번에 실행하는 출시 후보 검증입니다.

## 내부 테스트 기준

- [ ] 최소 3명 이상 설치 테스트
- [ ] 실제 기기 2종 이상 확인
- [ ] 외부 링크 열기 확인
- [ ] 앱 삭제 후 재설치 확인
- [ ] Play Console pre-launch report 확인
- [ ] `docs/launch-day-checklist.md` 기준으로 제출 24시간 전, Play Console, App Store Connect, 출시 후 72시간 항목 확인
- [ ] `docs/store-assets-guide.md`의 스크린샷 스토리보드 기준으로 홈, 검색/필터, 상세, 찜, 알림, 마이 화면 촬영

## 테스트 종료 기준

- 자동 검증 명령이 모두 성공한다.
- 실제 Android 기기 또는 Emulator에서 홈, 상세, 찜, 알림, 마이, 외부 링크 이동을 1회 이상 확인한다.
- 링크 검수 큐의 상위 상품을 확인하고, 직접 구매 URL이 없는 항목은 `판매처 검색 확인` 상태로 유지한다.
- signed AAB 업로드 전 `docs/release-checklist.md`의 High 항목을 완료한다.
